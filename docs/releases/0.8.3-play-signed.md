# MinIME 0.8.3: upload-signed AAB

September 12, 2026. Authorized local signing/release tooling change. The
previously verified release AAB is now signed with a dedicated RSA-3072 upload
key, using SHA256withRSA and SHA-256 entry digests. The signing certificate uses
CN=MinIME Upload and expires January 28, 2054. It is separate from the development
certificate used by sideload test APKs. No runtime or dictionary changes.

Download: `artifacts/downloads/MinIME-0.8.3-play-signed.aab` (92,164,886 bytes).
Artifact and public-certificate hashes are in `0.8.3-play-signed.json`.
The older combined ZIP remains an immutable archive containing unsigned files;
use this new AAB for the signing step of Play preparation.

## Key storage and reuse

Private key: `.tools/signing/minime-upload.jks`, alias `minime-upload`.
Password: `.tools/signing/password.dpapi`, encrypted for this Windows user on
this computer. The directory has inheritance disabled and permits only the
current Windows user. Both files are excluded from Git and distribution archives.
Public certificate: `artifacts/downloads/MinIME-upload-certificate.pem`.

Keep a secure backup of the keystore and its password. Copying only the DPAPI
file to a different machine is not a portable password backup. Secure backup
outside this computer has not been arranged. Do not put the private key or
password in downloads, transcripts, source archives or the repository.

Set JAVA_HOME to JDK 17, then sign future locally built release bundles with:

```powershell
./tools/sign-play-bundle.ps1 -Bundle app/build/outputs/bundle/release/app-release.aab `
    -Output artifacts/downloads/MinIME-NEXT-play-signed.aab
```

The script defaults to the existing key. `-CreateUploadKey` is for initial setup
only and refuses an existing signing directory. Existing output files are also
refused. Passwords are passed through a temporary process environment variable
and restored/cleared afterward. This helper does not upload to Play, invoke CI,
or change Gradle's environment-based signing policy.

## Verification and limits

- Bundletool validates the signed AAB; 24 runtime assets and all four native ABIs
  match the expected inventory, with compatible 16 KB ELF alignment.
- Jarsigner verifies; the independent Java checker reads all 69 payload entries
  and requires the exported upload certificate on every one. An unsigned bundle
  is rejected. All original ZIP entry contents remain byte-identical; signing
  adds only META-INF metadata and the JAR signature.
- A second signing run successfully decrypts the persisted password and reuses
  the same certificate. This caught a newline parsing issue in DPAPI loading;
  the loader now trims the serialized line before decoding. Restricted-directory
  checks require the owning Windows user; the public certificate is separately
  exported so routine verification needs no access to private key storage.
- Jarsigner's self-signed-chain and absent-timestamp warnings are recorded;
  Android upload certificates are self-signed. Identity is verified against the
  independently exported certificate, rather than a public CA trust chain.
- Core and device tests are not rerun for signing unchanged payloads. No device
  operations, Play upload or GitHub CI took place.

The upload key is created locally but is not registered in Play Console yet.
Play App Signing still needs configuration at the first release. Existing
source-rights review and Android 16 / 16 KB runtime gates remain open; successful
signing does not close them or establish Play acceptance.
